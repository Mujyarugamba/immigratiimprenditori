## 3. Architecture decision

**Chosen:** separate table `person_contact_channels` + SECURITY DEFINER RPCs + legacy `profiles.phone` forced NULL.

**Rejected as insufficient:** hide-in-React only; same-row RLS column masking; relying solely on `REVOKE SELECT (phone)` under table-level `GRANT ALL` to `anon` (observed: `attacl` remained null; `has_column_privilege` still true).

## 7. Security notes

- Service role remains server-only (unchanged).
- RPCs: `SECURITY DEFINER` + `search_path = public`; grants narrowed.
- No join leakage of contact values into public person select.
- Pre-existing broad `anon` table privileges on `profiles` are **out of L1.1b scope** except legacy phone emptied + check constraint.
- Scraping by registered users who can call network RPC is not prevented (documented).
